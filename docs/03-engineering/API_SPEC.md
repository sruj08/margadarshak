# API Specification
> Project: Margdarshak · Owner: Backend lead · Status: Draft v0.1 · Last updated: 2026-10-24 (P2 delta)
> Related: [OpenAPI 3.1 contract](../../api/openapi.yaml) · [Architecture](ARCHITECTURE.md) · [Data model](DATA_MODEL.md) · [Integrations](INTEGRATIONS.md) · [Tech stack](TECH_STACK.md) · [PROJECT_BRIEF §7](../00-overview/PROJECT_BRIEF.md)

The machine-readable contract is `api/openapi.yaml` (OpenAPI **3.1.0**, JSON Schema 2020-12). It was validated on 2026-10-23 with `openapi-spec-validator` 0.9.0 (84 paths, 127 schemas); with the P2 delta (games, learning, gamification, clip bank, online field study; 2026-10-24) it has 107 paths and 180 schemas. This document explains the conventions and lists every API-xx with an example. **If the two disagree, `openapi.yaml` wins and this file is corrected.**

Every operation in the YAML has `x-api-id`. Operations marked `x-proposed: true` are not in PROJECT_BRIEF §7 yet; they are needed to make the listed endpoints work (auth, helper links, tenant config, identity, payment hand-off, DigiLocker). They are reported to the brief owner for ratification (see §6).

Labels "P2 D-xx" point to the decision log of the P2 OpenAPI delta (P2 D-01…D-32); a bare "D-xx" is a PROJECT_BRIEF decision.

## 1. Conventions

### 1.1 Style
- **REST over HTTPS + JSON**, one WebSocket (API-40). No GraphQL: the surface is small, cacheable and must be easy for NIC/state teams to audit and re-implement.
- Resource names are plural nouns; actions that are not CRUD are sub-resources (`/complete`, `/submit`, `/approve`, `/join`).
- JSON field names are `snake_case`. Three game-core objects keep game-core's `camelCase` keys: `SessionResult`, `SessionContext` (`ctx` in API-34) and `ReplayPackage` (`replay` in API-35). They are validated by the same Zod schemas on the device, handed unchanged to the game module or the score verifier, and replayed byte-for-byte. Envelope keys around them (`ctx`, `replay`, `client_result`) and everything else stay `snake_case` (P2 D-02).
- IDs are opaque prefixed strings (`cas_`, `pln_`, `off_`, `hlp_`, `cns_`, `fam_`…; P2 adds `sqd_` squads, `shc_` share cards, `rtg_` clip ratings, `rvt_` clip review tasks); game session IDs are UUIDv7.
- Clips use the clip-pipeline format `KL-0007` (2–4 capital letters, a hyphen, 4–6 digits) plus an integer `version`; item refs are `clip:KL-0007@1`, not `clip_…`. Field-study participants are `P-017`.
- Share-card wire IDs are `shc_` + the upper-cased 10-character short ID that the database stores (`game.share_cards.short_id`, DATA_MODEL §4.5).
- **Time:** RFC 3339 UTC timestamps; calendar dates are ISO 8601 in the Asia/Kolkata calendar. Every case response carries `server_time`; clients must not compute deadlines from the device clock (EC-15).
- **Money:** integer **paise** in `amount_paise` (70000 = ₹700), the unit of `fees.json` (BACKEND.md §6), always computed from the tenant's rule pack (CMVR r.32). No floats in money paths and no rupee literal in code, prompts or UI strings (D-06).
- **Wire casing:** JSON is `snake_case`; `packages/api-client` (generated by `openapi-typescript` from `api/openapi.yaml`) maps to the camelCase names used in FRONTEND (`displayStage`, `primaryAction`) through one typed mapper. See §6 item 9.
- **Tenant header:** every request sends `X-Tenant: <state code>` (FRONTEND §4), which must match the session's tenant and the host's allowed tenants.
- **Localisation:** responses carry i18n keys (`title_key`, `fix_key`) plus rule text in `en`/`hi`; the client renders the user's language. `Accept-Language` selects AI narration language.
- **Provenance everywhere:** any rule-derived value carries `rule_id` and a `Provenance` object (`source_title`, `source_url`, `verified_on`, `confidence`, `verified`). Rows with `verified: false` are shown with "verify at your RTO" and are never citable by AI.

### 1.2 Versioning
- Major version in the path: `/v1`. Within v1, changes are **additive only** (new optional fields, new endpoints, new enum values announced 30 days ahead because clients must tolerate unknown enum values).
- Breaking changes go to `/v2`, with `/v1` kept for at least 6 months, announced with `Deprecation` (RFC 9745) and `Sunset` (RFC 8594) headers and a CHANGELOG entry.
- Rule-pack versions are **data versions**, separate from API versions: responses include `rule_pack.version`; a case is pinned to the version it started on until re-evaluated (EC-27).
- Game scoring is versioned with the manifest (`scoring_version`); the verifier keeps every published scoring version so old sessions replay identically.

### 1.3 Authentication and scopes
| Scope | Who | How obtained | Typical rights | Notes |
|---|---|---|---|---|
| *(public)* | anyone | none | plan, rules, offices, intel, modules, clips, share cards, record check, public stats, health | no cookies; CDN-cacheable |
| `anon` | anonymous device | API-06 `POST /v1/sessions/device` → opaque `md_sid` cookie (HttpOnly, Secure, SameSite=Lax) | own cases, autosave, games, answers, consents | data lives server-side but tied to a device; upgrade to account keeps it |
| `user` | account holder (email magic link or Google) | API-07 → API-08 | everything the account holder and their family-mode cases own; every AI feature with purpose consent (D-13 revised) | **never Aadhaar-OTP login** (brief §15) |
| `helper` | family member or CSC/cyber-café operator acting for an applicant | API-58 helper link accepted; the helper's session gets an `acting_for` grant on that case | only the permissions on the link (`case.read`, `case.write_answers`, `case.record_events`, `learn.read`, `letters.draft`) | revocable in 60 s (EC-25); every action audit-logged with both identities |
| `school` | driving-school staff | invited by school owner; account + `eco.school_staff` row | API-52 only, for learners who consented (`school_share`) | |
| `console` | state/RTO officer | provisioned by tenant admin; production: state SSO/Jan Parichay via adapter `[unverified]` | API-53 aggregated views only (k-anonymity) | no row-level citizen data |
| `admin` | Margdarshak or state staff | provisioned; hardware-key 2FA in production | sub-roles `admin:rules.maker`, `admin:rules.checker`, `admin:clips.curator`, `admin:clips.rater`, `admin:moderation`, `admin:field_study` | maker ≠ checker enforced in code and DB |
| `internal` | n8n, Render Workflows tasks, payment adapter | **service bearer token** (`Authorization: Bearer`, per caller) **plus** HMAC body signature `Margdarshak-Signature: t=…,v1=…` (SHA-256, 5-min window, nonce replay cache in Key Value) | `/internal/*` only (API-24, API-65..69, API-72, API-73) | n8n never queries Postgres directly; secrets rotated quarterly |

Sessions (aligned with BACKEND.md §12): an opaque 256-bit session token in the `md_sid` cookie; the session record (Key Value, 180-day sliding TTL) holds `principal`, `scope`, `tenant`, `age_band`, active consent purposes and helper grants. Account upgrade (magic link / Google) rotates the token. Unsafe methods require `X-Requested-With: margdarshak` (CSRF defence with SameSite=Lax). Non-browser clients may send the same token as `Authorization: Bearer`. The voice WebSocket uses a 60-second single-use ticket from `POST /v1/voice/ticket`, not the cookie.

**Gates applied in the Go chi middleware chain (`internal/httpapi`) before any handler:**
1. scope check;
2. tenant match (`tenant` claim = resource tenant, enforced again by Postgres RLS);
3. **family-mode gate** (D-13 revised): there is no age gate on any feature, AI included. When a case belongs to a learner under 18 (`for_family_member: true`, `age_band` `under_16` or `16_17`), the adult account holder's verifiable parental consent must be on record, else `403 PARENT_CONSENT_REQUIRED`; analytics events (API-63) are never stored for that learner. Three features need a separate parental extra on top of the base consent: `squads` (API-39), `share_cards` (API-57) and `pair_mode` (API-34 `mode: pair`), set through API-60's parental-consent operation; without it the answer is `403 PARENT_CONSENT_REQUIRED`;
4. **consent gate**: e.g. `ai_coach` for debrief narration, `ai_voice` for API-40, `whatsapp_updates` for API-04 → `403 CONSENT_REQUIRED` with the purpose to request.

### 1.4 Errors (RFC 9457)
All errors are `application/problem+json` with the codes of BACKEND.md §14:
```json
{
  "type": "https://margdarshak.example/problems/validation-failed",
  "title": "Validation failed",
  "status": 422,
  "code": "VALIDATION_FAILED",
  "detail": "1 field failed validation",
  "instance": "/v1/cases/cas_01JB8ZC",
  "trace_id": "01JB8ZT…",
  "title_key": "errors.validation",
  "retryable": false,
  "errors": [ { "pointer": "/answers/aadhaar_number", "code": "PROHIBITED_FIELD", "message_key": "errors.prohibited_field" } ]
}
```
The `type` host is a placeholder until the domain is registered (owner Backend lead, 2026-10-30). Catalogue:

| `code` | Status | When |
|---|---|---|
| `VALIDATION_FAILED` (+ `PROHIBITED_FIELD` per error item) | 422 | schema failure; Aadhaar number, OTP, password or personal-vault key sent |
| `UNAUTHENTICATED` | 401 | missing/expired session, bad internal token or HMAC |
| `FORBIDDEN` | 403 | scope, role or tenant mismatch |
| `PARENT_CONSENT_REQUIRED` | 403 | a family-mode case of a learner under 18 has no verifiable parental consent from the adult account holder on record (D-13 revised) |
| `CONSENT_REQUIRED` | 403 | purpose consent missing or revoked |
| `MAKER_CHECKER` | 403 | checker equals maker |
| `NOT_FOUND` | 404 | also used instead of 403 to avoid leaking existence |
| `GONE_DELETED` | 410 | account/case deleted (EC-26); revoked Practice Record token |
| `JOURNEY_INVALID_TRANSITION` | 409 | event not allowed in the current journey state |
| `IDEMPOTENCY_IN_PROGRESS` | 409 | same key still in flight (`Retry-After: 1`) |
| `PRECONDITION_FAILED` | 412 | `If-Match` stale (edited on another device) |
| `IDEMPOTENCY_KEY_REUSED` | 422 | same key, different body |
| `SESSION_EXPIRED` / `REPLAY_REJECTED` | 409 / 422 | game session closed / the verifier rejected the replay inputs (session voided). A late API-35 is not an error in P2: it is flagged `INT_SESSION_EXPIRED` |
| `NO_UNSEEN_CLIPS` | 409 | API-34 mock: not enough mock-eligible clips this subject has never seen (practice still works) |
| `SESSION_ALREADY_COMPLETED` | 409 | API-35 again with a different `replay.digest` (the same digest returns the stored result) |
| `SESSION_NOT_COMPLETED` | 409 | replay endpoint called before API-35 |
| `PAYLOAD_TOO_LARGE` | 413 | API-35 replay over 512 KB |
| `SQUAD_FULL` / `INVITE_EXPIRED` | 409 | API-39 join: squad has 5 members / invite older than 7 days |
| `SHARE_CARD_NOT_ALLOWED` | 422 | API-57 create without a Nazar-Score-eligible mock |
| `ACCOUNT_REQUIRED` | 403 | an account-only feature (squads, share cards, Khud Licence declaration) called from an anonymous device session |
| `CLIP_INVALID_TRANSITION` | 409 | API-55 action not allowed in the clip's status (clip-pipeline `transition`) |
| `RATING_ALREADY_SUBMITTED` | 409 | API-55 a rater rates the same clip version twice, or both ratings are already stored |
| `ADJUDICATOR_IS_RATER` | 403 | API-55 adjudication by one of the two raters |
| `BLUR_AUDIT_FAILED` | 422 | API-55 blur audit that does not cover 100% of frames with 0 misses on the rendition to publish |
| `RATE_LIMITED` / `VOICE_QUOTA_EXCEEDED` | 429 | with `Retry-After` |
| `RULEPACK_UNAVAILABLE` | 503 | no approved pack for the tenant ("we don't know for your state yet") |
| `ADAPTER_UNAVAILABLE` | 503 | e.g. Sarathi outage (EC-11), verifier down; body says which fallback applies (`offline_draft`, `template_debrief`) |
| `INTERNAL` | 500 | unexpected; details only in logs by `trace_id` |

Error text never echoes user input, never contains PII, and AI failures never surface model output.

### 1.5 Idempotency
- Header `Idempotency-Key` (UUIDv7 recommended, 16–64 chars). **Required** on API-04, API-15, API-35, API-44, API-45, API-49, API-51, API-54 approve, API-65 and all webhooks; P2 adds API-57 create, API-39 leave, API-55 blur audit and adjudication, the two `/internal/clips/*` endpoints and API-70 study enrolment. Optional elsewhere.
- Stored in `ops.idempotency_keys` for 24 h, keyed by `(scope subject, key)` with a SHA-256 of the canonical body. Replay with the same body returns the stored status + body and header `Idempotent-Replayed: true`; a different body returns `422 IDEMPOTENCY_KEY_REUSED`; a request still in flight returns `409 IDEMPOTENCY_IN_PROGRESS`.
- Domain-level idempotency backs it up: case events are unique on `(case_id, idempotency_key)`, answers on `client_answer_id`, game completion on `session_id` + `replay.digest`, timeline rows on their deterministic key, notifications on `{timelineEventKey}:{channel}` (timeline key `{caseId}:{milestoneId}:{dueOn}`), webhooks on `(event, id)`.
- Offline clients (Lite mode) queue writes in IndexedDB with their key and replay on reconnect.

### 1.6 Concurrency
`GET /v1/cases/{id}` returns `ETag: W/"<version>"`. `PATCH` requires `If-Match`; on mismatch the client fetches, merges field-by-field (last writer per field) and retries. This is how "resume on any device" (F-05) avoids silent overwrites.

### 1.7 Pagination and filtering
Cursor pagination: `?cursor=<opaque>&limit=1..100` (default 20) → `{ "items": [...], "next_cursor": "..." | null }`. Cursors are signed, encode the sort key, and expire after 24 h. No offset pagination (stable under inserts, cheap at scale).

### 1.8 Rate limits
Announced with the IETF `RateLimit-Policy` / `RateLimit` headers (draft-ietf-httpapi-ratelimit-headers); `429` carries `Retry-After`. Implemented with the `limits` library (5.8.0) on Render Key Value (sliding window); per-IP limits use the client IP from Render's proxy header.

### 1.9 Caching and offline
- Rule, office, module and clip responses send `ETag` + `Cache-Control: public, max-age=300, stale-while-revalidate=86400`; the PWA service worker (Serwist) caches them for offline use.
- Clip media is served from object storage/CDN with `Accept-Ranges` (Range requests needed for `<video>` from the SW cache).
- The plan card is cached on the device after API-01, so it opens offline.

### 1.10 Webhooks (outbound) and callbacks (inbound)
- **Citizen messages do not go through n8n** (ADR-0006 rev. 2026-10-24). They are `ops.outbox` rows sent by the backend notifier (`NotificationPort`: `WhatsAppCloudNotifier`, `EmailNotifier`, `WebPushNotifier`, `ConsoleNotifier`), at-least-once with exponential retry up to 24 h.
- **Outbound to n8n** (staff work only, from `ops.outbox`): `POST {N8N_BASE}/webhook/<flow>` with `Margdarshak-Signature`, at-least-once, exponential retry up to 24 h. Flows: `school-lead` (W07), `clip-review` (W08), `intel-moderation` (W09, flagged reports only), `alert` (W12), `field-session` (W14), `console-alert` (W17).
- **Inbound from n8n** (internal scope; n8n never queries Postgres): API-65 clock sweep (W01), API-66 staff receipts/decisions/acknowledgements, API-67 start a job (e.g. `clip_finalize` after the two-rater wait in W08), API-68 Live Intel decision for flagged reports (W09), API-73 next school for a lead (W07). **Inbound from Meta and the email provider**: API-66 citizen delivery receipts, replies and STOP (EC-30). **Called by the backend internally, not by n8n**: API-68 precheck (inline on API-28), API-69 fire slot watchers (from the API-68 decision handler), API-72 dispatch a user-approved letter. **Inbound from the payment adapter**: API-24.
- An AsyncAPI 3.0 description of these events is roadmap (owner Backend lead, Phase 3).

### 1.11 Observability headers
Requests accept/return W3C `traceparent`; responses add `X-Request-Id`. Logs are structured (Go `log/slog` JSON) with PII redaction before export (OpenTelemetry → collector).

## 3. Endpoints

Examples are abbreviated; the full schemas and examples are in `api/openapi.yaml`. "Errors" lists the non-generic problems (every endpoint can also return 400/401/429/5xx).

### 3.1 Plan and rules

#### API-01 `POST /v1/plans` — 3-tap licence plan (F-02, F-03, F-04)
Scope: public (optional anon). Rate: plan tier. Idempotency: optional. Pure rules-engine call; no AI; DOB is reduced to an age band and key birthdays; snapshot kept 7 days.
```json
// request
{ "state": "JK", "dob": "2007-03-14", "dob_precision": "day", "vehicles": ["motorcycle", "car"],
  "aadhaar_address_matches_residence": true, "already_holds_ll": false, "language": "hi" }
// 201 response (abridged)
{ "plan_id": "pln_01JB8Z6X3V9Q2K7M4N5P6R7S8T",
  "rule_pack": { "pack_id": "JK", "version": "2026.10.0", "base_version": "IN-base@2026.10.0" },
  "age_band": "18_25",
  "eligible_classes": [ { "class_code": "MCWG", "eligible": true, "content_depth": "deep", "rule_id": "ELIG-MCWG-AGE" },
                        { "class_code": "LMV-NT", "eligible": true, "content_depth": "deep", "rule_id": "ELIG-LMV-NT-AGE" } ],
  "recommended_bundle": { "classes": ["MCWG", "LMV-NT"], "saving_note_key": "plan.bundle.saves_second_wait_if_sequential" },
  "max_rto_visits": 1,
  "earliest_dates": { "ll_issue": "2026-10-24", "dl_test_unlock": "2026-11-23", "earliest_licence": "2026-11-23" },
  "fees": { "lines": [ "…7 lines from fees.json…" ], "subtotal_govt_fee_paise": 115000, "total_paise": 135000,
            "excludes": ["state_service_charge", "postage"],
            "provenance": { "source_title": "CMVR 1989 r.32", "verified_on": "2026-10-22", "confidence": "medium", "verified": true } },
  "documents": [ { "doc_id": "proof_of_age", "required": true, "rule_id": "DOC-AGE" } ],
  "blockers": [], "disclaimers": ["not_affiliated", "verify_at_rto_for_transport"], "expires_at": "2026-10-31T03:30:00Z" }
```
Fee check (CI golden test, paise): one class = 15000 + 5000 + 30000 + 20000 = **70000** (₹700), + 20000 smart card = 90000 (₹900); MCWG + LMV-NT = 115000 + 20000 = 135000 (₹1,350). `dl_test_unlock` comes from the rule pack's `min_wait_days` (brief §15). Edge cases: EC-01 (`dob_precision: year_only` → blocker asks for a DOB document), EC-05 (16–17 → only MC50CC with guardian consent, "most scooters exceed 50 cc"), EC-06 (transport under 20 → not eligible), EC-10 (no online LL test → plan says "test at RTO"), EC-21 (two classes, different ages → `eligible_from`). Errors: 422 `VALIDATION_FAILED`.

#### API-02 `GET /v1/rules/{state}/classes`
Scope: public. Returns every class (all classes are in the engine, D-05) with `min_age_years`, `medical_form_1a`, `transport`, `content_depth` (`deep` only for MCWOG/MCWG/LMV), flags such as `verify_at_rto`, `lmv_prerequisite_unverified`, and provenance. `?version=` pins a pack version. 304 on ETag match.
```json
{ "state": "JK", "classes": [ { "class_code": "LMV-TR", "min_age_years": 20, "medical_form_1a": "always", "transport": true,
  "content_depth": "coming", "rule_id": "ELIG-TRANSPORT-AGE", "flags": ["verify_at_rto", "lmv_prerequisite_unverified"],
  "provenance": { "source_title": "MV Act 1988 s.4", "verified_on": "2026-10-22", "confidence": "low", "verified": false } } ] }
```

#### API-03 `GET /v1/rules/{state}/fees?classes=MCWG`
Scope: public. Fee table (`fee_id`, `per`, `amount_paise`, `rule_id`) plus a computed `quote` when `classes` is given (one class → `subtotal_govt_fee_paise: 70000`, `total_paise: 90000`).

#### API-04 `POST /v1/plans/{planId}/whatsapp`
Scope: anon or user. Idempotency: required. Creates a `whatsapp_updates` consent artefact, stores the phone encrypted (E-14) and queues the approved template `plan_card_v1` in the outbox; the backend notifier (`WhatsAppCloudNotifier`) sends it through the Meta WhatsApp Cloud API (n8n is not on this path). Hackathon: Meta test number, allow-listed recipients only (R-08).
```json
// request
{ "phone_e164": "+919876543210", "consent": { "purpose": "whatsapp_updates", "notice_version": "notice-2026.10.23-hi", "granted": true }, "language": "hi" }
// 202
{ "notification_id": "ntf_01JB8Z7C", "status": "queued", "channel": "whatsapp", "template_id": "plan_card_v1" }
```
Errors: 404 plan expired; 422 `IDEMPOTENCY_KEY_REUSED`; status `suppressed_opt_out` after STOP (EC-30).

#### API-05 `GET /v1/rules/{state}/ll-format`
Scope: public. LL test format for the simulator (F-22): questions, pass mark, timers, where held, languages, provenance. Unknown formats return `known: false` and the simulator shows "format unknown for your state" with the default.
```json
{ "state": "JK", "rule_id": "LL-FORMAT", "known": true, "questions": 10, "pass_correct": 6, "pass_pct": 60,
  "online_test_available": true, "where": ["home_online", "csc", "rto"],
  "provenance": { "source_title": "Kashmir Life, Dec 2025, quoting the Srinagar ARTO", "verified_on": "2026-10-22", "confidence": "low", "verified": false } }
```

```json
  "disclaimer_key": "footer.not_affiliated_simulated_data" }
```

### 3.2 Auth and helpers *(all proposed)*

#### API-06 `POST /v1/sessions/device`
Scope: public. Creates an anonymous device session; web clients get `Set-Cookie: md_sid=…; HttpOnly; Secure; SameSite=Lax`. `201 → { scope: "anon", subject, age_band: null, expires_at }`.

Scope: anon. Emails a single-use link (10 min). Always `202 { "status": "accepted" }` (no account enumeration).

#### API-35 `POST /v1/games/sessions/{sessionId}/complete`
Idempotency required. Body (`GameSessionComplete`): `client_result` (the client `SessionResult` preview; its `replay.inputs` should be empty) + `replay` (game-core `ReplayPackage`: `telemetryVersion, encoding, inputs, digest, eventCount`) + optional `commentary`. The API sends the replay and the session's items (scoring documents inline) to the **score verifier** (Node, `@margdarshak/game-core`) over the private network (2 s budget); the server score **overwrites** the client score and is the one that counts (D-11). A mismatch adds `INT_REPLAY_MISMATCH` (never an accusation); a client preview with `score.max == 0` (the web's mock mode) is never compared, so it never adds `INT_REPLAY_MISMATCH`. Nazar: UK-style 5 bands per hazard, scaled to Kerala's 10 marks per clip (`nazar.rule: kerala_5band`); **more than 3 taps per second voids the clip** (config value, brief §15). Completing after `expires_at` is allowed and flagged `INT_SESSION_EXPIRED`. Request body limit 640 KB (512 KB replay + the preview).

#### API-55 Clip admin (`/v1/admin/clips/...`)
`POST /v1/admin/clips` registers a raw upload (filmed by a passenger or a fixed mount, never the rider; contributor consent; CC-BY 4.0) and starts the `clip_ingest` workflow → `202 Clip { status: "raw", workflow_runs: [...] }`. `GET /v1/admin/clips/{id}` shows status, Gemini proposals (±1 s; never used for scoring), ratings, agreement, review tasks and run IDs. `POST …/ratings` (two independent raters; the blur audit is its own operation) and `POST …/publish` (only after agreement passes and blur audit is 100%; AI never auto-publishes).

P2 (P2 D-12 to P2 D-15). Clip IDs are `KL-0007` with an integer `version`; the actor pseudonym (`curator-01`, `rater-02`) always comes from the session, never the body.
- **Statuses** (clip-pipeline `ClipStatus`): `raw → transcoded → blurred → audited → proposed → (adjudication) → rated → published`, and any status → `retired`. In-flight work shows in `workflow_runs`; a failure is a failed job run; a rejection is `retired`.
- **Register** body `ClipRegister`: `raw_object_key, state, tenant_tags, filmed_by, city` (letters only), `road_type, time_of_day, weather, pov, captured_month` (YYYY-MM, never a date), `speed_kmh_est, speed_source, licence, contributor_consent_id` (P2 D-17).
- `GET /v1/admin/clips` (`listClipsAdmin`): the curator board, filtered by `status` and `state`. Curators see every clip; a rater sees only clips with a review task assigned to them.
- **Blindness** (NAZAR §6.2): until both ratings of the current version exist, a rater sees only `my_rating`, no proposals and no agreement; `ratings_visible` and `proposals_visible` say what the caller may see.
- **Ratings** (`ClipRatingCreate`, admin:clips.rater): `version, review_task_id, decision` (`windows_set | reject`), `marks[] { hazard_type, a_ms, b_ms, cue, occlusion }` (≤ 10). It is the blind clip-pipeline `RaterSubmission` without the blur flag. A second rating by the same rater → 409 `RATING_ALREADY_SUBMITTED`. Storing a rating resumes the rater's n8n W08 wait; after the second rating W08 calls API-67 `clip_finalize`.
- `POST …/blur-audit` (`recordClipBlurAudit`, curator as auditor): `version, rendition_sha256, frames_total, frames_checked, misses, miss_frames`. It passes only at 100% of frames, 0 misses and the sha256 of the rendition to publish (422 `BLUR_AUDIT_FAILED` otherwise); a failed audit sends the clip back to `blurred` for a re-blur.
- `POST …/adjudication` (`adjudicateClip`): only in status `adjudication` (409 `CLIP_INVALID_TRANSITION`). The adjudicator must not be one of the two raters (403 `ADJUDICATOR_IS_RATER`). Body `version, reason_code, decisions[]`. A resolved adjudication moves the clip to `rated`.
- `PUT …/cue-texts` (`setClipCueTexts`, *proposed*): the curator's cue per final hazard of a `rated` clip, in English and Hindi (≤ 160 characters each). Body `{ version, cues: { "<hazard_id>": { "en": "…", "hi": "…" } } }`. 409 `CLIP_INVALID_TRANSITION` in any other status; 422 for an unknown hazard ID or a cue naming a person, phone, vehicle number or exact place. Publish needs a cue for every final hazard.
- `POST …/publish`: the curator's manual path for a `rated` clip (normally the `clip_finalize` step `clip.publish_manifest` publishes); 409 `CLIP_INVALID_TRANSITION` unless clip-pipeline `transition(clip, published)` holds.
- **W08 internal endpoints** *(proposed; internal bearer + HMAC)*:
  - `POST /internal/clips/{clipId}/review-tasks` (`createClipReviewTask`): body `stage` (`rater_1 | rater_2`), `resume_url` (stored encrypted), `n8n_execution_id`, `due_in_hours`, `exclude_rater_id`, `blind_to_rater_1`. Idempotent on (clip, version, stage); only in status `proposed`.
  - `POST /internal/clips/{clipId}/status` (`setClipReviewOutcome`): body `status` (`rejected | review_timeout`), `stage`, `n8n_execution_id`. `rejected` retires the clip version; `review_timeout` leaves it in `proposed` with the task `timed_out`.
```json

{ "version": 1, "review_task_id": "rvt_01JB9A2", "decision": "windows_set",
  "marks": [ { "hazard_type": "truck_left_turn", "a_ms": 18000, "b_ms": 22500, "cue": "Truck turning left across your path", "occlusion": false } ] }
// 201 → { "rating_id": "rtg_01JB9A3", "clip_id": "KL-0007", "version": 1, "rater": "rater-01", "decision": "windows_set", "marks": [ … ], "submitted_at": "…" }
```

#### API-69 `POST /internal/watchers/{slotWatchId}/fire`

### 3.11 Field study

#### API-70 `POST /v1/lab/trials`
Journey-test trial (F-57) with pseudonymous participant code, arm (`portal_replica` | `margdarshak`), task, timings, errors, SUS, "would you still pay an agent?". 18+ and consent `field_study`; pre-registered in `HYPOTHESES.md`.

#### API-70 `POST /v1/study/nazar/enrolments` *(proposed)*
`enrolNazarStudy`. Scope: anon/user (device session); **not token-gated**, unlike lab trials, because the online Nazar study runs from a QR link (P2 D-19). Called only after the consent screen and an active `field_study` consent for this session (403 `CONSENT_REQUIRED` otherwise); declining means no call and nothing stored. 18+ only (`age_ok: true`). Body `StudyEnrolmentCreate`: `consent_id` (optional; the server looks up the active one), `age_ok`, `age_band` (`18_20 | 21_24 | 25_34 | 35_plus`), `licence_held` (`ll | 2w | 4w | both`), `years_driving` (`0_1 | 1_3 | 3_plus`), `retake_of`. Forms rotate A → B → C by arrival order. Enrolling again from the same session returns the existing participant with 200; a retake is a new participant with `retake_of`. The study cohort gets template debriefs only (`ai_debrief: false` by default).
- `phases` lists `ll_mock`, `test`, `feedback`, `fresh`. `ll_mock`, `test` and `fresh` are API-34 sessions with `study`; `feedback` is the replay endpoint on two test clips, not a session phase (P2 D-20).

```json
{ "age_ok": true, "age_band": "21_24", "licence_held": "ll", "years_driving": "0_1" }
// 201 → { "participant_code": "P-017", "form": "B", "cohort": "field_test", "phases": [ { "phase": "ll_mock", "game_id": "ll_sim", "item_count": 15 }, … ], "ai_debrief": false, "created_at": "…" }
```

#### API-70 `POST /v1/study/nazar/enrolments/{participantCode}/near-miss` *(proposed)*
`recordNazarNearMiss`. Optional one-line near-miss story (`text` ≤ 140 characters, `language`), written only by the session that enrolled the participant (404 otherwise). Privacy-scanned before storage: a name, phone number, vehicle registration, licence number or exact place is rejected with 422 `PROHIBITED_FIELD` and nothing is stored (P2 D-21). Never exported to the CSVs; a second call replaces the line. `204`.

#### API-71 `GET /v1/stats/public`
Live counters for judges (recomputed nightly by `nightly_stats`, plus live counts): Nazar n, share below Kerala's 60/100, r(LL quiz, Nazar) with 95% CI, journey-test medians, "convenience sample" disclaimer. No mortality or crash-reduction claims (D-22).
P2 (P2 D-23): `nazar` is the latest `study.public_stats` payload (what `stats.field_study_publish` stored from `field-kit/nazar_stats.mjs`, run unmodified on the exported CSVs) merged with `script_sha256`, `as_of` and `prereg_hash`. Documented fields: `status` (`collecting` until the first publish, then `published`), `sample` (`convenience`), `participants` (N after the pre-registered exclusions), `below_kerala_60_pct`, `ci95`, `r_ll_quiz_vs_nazar`, `r_ci95`, `median_late_s`, `prereg_hash`, `script_sha256`; other keys are allowed. `counters` gains `game_sessions_counted` and `nazar_participants` (the live enrolment count).

```json
  "counters": { "game_sessions_counted": 212, "nazar_participants": 51 } }
```

#### API-71 `GET /internal/study/exports/{file}` *(proposed)*
`exportStudyFile`. Scope internal (bearer + HMAC). The `nightly_stats` task reads `sessions.csv`, `sessions_alt.csv`, `raters.csv` and `clip_responses.csv` (columns exactly FIELD_STUDY §7.1; P2 D-22) as `text/csv`. ## 4. Contract testing and SDKs
- **Spec lint:** `@redocly/cli` 2.70.0 `lint` + `@stoplight/spectral-cli` 6.17.0 with rules: every operation has `x-api-id`, an example, a `security` entry, and 4xx problem responses.
- **Server conformance:** the Go integration suite (`go test` with embedded Postgres) validates every request and response it makes against `api/openapi.yaml` with `github.com/getkin/kin-openapi` v0.152.0 (`openapi3filter`), including problem responses.
- **Spec-to-code drift:** the server is generated **from** the spec (contract-first): `oapi-codegen` v2.8.0 (`chi-server` + `strict-server` + `models`) writes `services/api/api/` from `api/openapi.yaml`; CI runs `go generate ./...` and fails on `git diff --exit-code`, and the build fails if a handler does not implement the generated strict interface.
- **Client:** `openapi-typescript` 7.13.0 generates types; `openapi-fetch` 0.17.0 is the typed client in `packages/api-client`. `msw` 3.0.3 mocks the API for frontend tests and for the offline demo.
- **Adapter contracts:** each government port has its own contract suite (ARCHITECTURE §5.3); the NIC/state side of each adapter is specified by the same schemas so a state can implement it without our code.

## 5. Security notes specific to the API
- CORS: only the web origin(s) from tenant config; no wildcard. CSRF is not applicable (bearer tokens, no cookies) except the DigiLocker callback, which validates `state` + PKCE.
- Request size caps: 64 KB JSON default, 640 KB API-35 body (512 KB replay + the client preview), 1 MB screenshot, 2 MB Aadhaar artefact (mock), 100 events analytics.
- All text inputs are length-capped; AI-bound text passes the PII gate (regex + Verhoeff for Aadhaar, 4–8-digit OTP, PAN, phone) before any model call (EC-20).
- `/internal/*` is not routed through the public CDN and additionally IP-allowlisted to n8n Cloud egress where n8n publishes ranges `[unverified]` (owner Platform lead, H+8). Exception: the channel-webhook handler of API-66 (Meta receipts, replies, STOP; email provider events) accepts provider IPs and is authenticated by the provider signature (`X-Hub-Signature-256` for Meta) instead, since citizen messaging no longer runs through n8n (ADR-0006).
